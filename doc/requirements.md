# asuyaru（明日やる）プロダクト要件

休日の前夜に、明日の時間割を組むアプリの要件である。
対象は一人の利用者、日本語、Mac である。
休日の朝は、時間割の最初のブロックから始める。
組んだ一日は、できた／できなかったと一言日記として残す。

ページは、その Mac 上の Golang が出す。
利用者は、その Mac のターミナルでローカルホストを起動し、その Mac のブラウザで開く。
動作するのは、ローカルホストを起動しているあいだだけである。

利用者は、TODO をプールに預け、予定と定期を登録する。
前夜に、翌日一日の時間割を出す。
出した時間割は残す。
あとから、ブロックごとにできた／できなかったを付け、一言日記を書く。

保存は SQLite ファイル一つである。

---

## 利用者

自分の休日を自分で決める一人である。
平日は仕事や学業があり、休日を自分のために使う。
「これやらなきゃ」と「いつかやりたい」が残り、休日になっても着手点が見えない。
組まれた時間割に乗る。
その日の約束と、曜日と時刻に紐づく生活の定期がある。

---

## タスク

タスクは、**予定**、**TODO**、**定期** の三つである。
一日に載らない大きさの TODO は、預けるときに分割する。

予定、定期、TODO は、いずれも **雨天中止** をオンかオフで持てる。
オフは **雨天決行** である。
雨天中止は、雨の日にその項目を時間割へ置かないことである。
雨天決行は、雨の日も置くことである。

### 予定

事前に決まっていた単発である。
開始時刻と所要時間を持つ。
カレンダーを先に占める。
前夜に、翌日（計画の対象日）の分として登録する。
属する日は、その計画の対象日である。

| 項目 | 意味 |
| --- | --- |
| 名前 | 「歯医者」など |
| 開始時刻 | 必須。時計時刻 |
| 所要時間 | 必須。分単位。終了時刻は開始に所要時間を足した時刻 |
| 雨天中止 | オンなら、その日が雨のとき時間割に置かない。オフなら雨天決行 |

例は、翌日の歯医者である。
8:00 から 10:00 を占める。
TODO はその枠に入らない。
雨天決行が普通である。

### TODO

事前に決まっていない単発、または恒常的にあるが時刻が決まっていないものである。
事前登録のプールである。
所要時間があり、開始時刻は生成が決める。
生成が空きに差し込む。

| 項目 | 意味 |
| --- | --- |
| 名前 | 着手時に何をするか分かる名前。必須 |
| 所要時間 | 必須。分単位。空きに入るかの判定に使う |
| 雨天中止 | オンなら、その日が雨のとき空きに入れない。オフなら雨天決行 |
| メモ | 任意。名前と所要時間への補足 |

やりたいことも、やらなきゃも、同じ TODO である。
プールに入っているものが空きを埋める。

完了した TODO に Done を付けられる。
達成確率は、フィードバックの内部パラメータである。
できた／できなかったと、未達の回数から出す。
未達は、できなかった件数と、未完了の件数である。

時刻が決まって繰り返すものは、定期として登録する。

### 定期

事前に決まっている定常登録である。
定義は残り、計画の対象日のうちルールに合う日に、開始時刻どおり展開される。

| 項目 | 意味 |
| --- | --- |
| 名前 | 「犬の散歩」「可燃ゴミ出し」など |
| 開始時刻 | 必須。時計時刻 |
| 所要時間 | 必須。分単位。終了時刻は開始に所要時間を足した時刻 |
| 繰り返し | 必須。曜日。複数の曜日を付けてよい |
| 雨天中止 | オンなら、その日が雨のとき時間割に置かない。オフなら雨天決行 |

繰り返しは曜日である。
終わったのは、その日の回だけである。
連休の翌日も、その日の曜日がルールに合えばまた出る。
雨天中止でその日置かなくても、次にルールに合う日の回は別である。

例は、犬の散歩である。
月–日、開始時刻つき、雨天中止である。
もう一つの例は、可燃ゴミ出しである。
火、金、雨天決行である。
計画する日が火または金なら、雨でも出る。

定期は、自分の開始時刻を占める。
その日の最後のブロックは、置かれたもののうち終了が最も遅いものである。

---

## 一日の範囲

TODO を置く範囲は、**起床** と **終わりの時間** で決まる。
共通の既定である。
前夜に、翌日の TODO の範囲だけを上書きしてよい。
上書きしたときはその値を使い、上書きが無いときは既定を使う。

| 項目 | 意味 |
| --- | --- |
| 起床 | TODO を置ける開始 |
| 終わりの時間 | TODO を置ける終わり |

予定と定期は、この範囲の外でも、開始時刻から終了時刻まで置く。
TODO だけが、起床から終わりの時間までに入る空きへ差し込まれる。

時間割の各ブロックは、開始時刻と終了時刻を持つ。

空きは、予定と定期を置いたあとの隙間である。
TODO は、その空きのうち、起床から終わりの時間までに入るものへ差し込む。

---

## 休日

休日は、計画を作った次の日である。
計画を作ることは、翌日が休みだという意味になる。
連休でも、その夜は翌日一日分だけを作る。
連休の翌日分は、その夜にまた計画を作る。

---

## 前夜に時間割を出す

入力は、その計画に登録した予定、曜日が合う定期、TODO プール、雨か（はい／いいえ）、起床、終わりの時間、余裕（あり／なし）である。

余裕は、前夜の疲れと、休みたい気持ちである。
余裕があるときは、TODO をきつめに詰める。
余裕が無いときは、きつめに詰めない。

Jev が決めるのは、数重視か時間重視かと、どの TODO を置くかである。
利用者は、数重視か時間重視かについては、その提案に従う。
その材料は、達成確率、所要時間、雨天中止、余裕である。
コードは、雨、予定、定期、起床から終わりの時間まで、余裕による詰め方を、登録された状態どおりに適用する。

Jev を呼ぶのは、利用者が計画を作るときと、その夜に計画を作り直すときである。
計画を 1 回作ること、または 1 回作り直すことが、Jev のリクエスト 1 回である。
失敗した呼び出しと、その再試行は、その 1 回に数える。
1 日あたり 3 回である。
3 回に達したら、その日はアプリがそれ以上の呼び出しを拒む。
目的は、ループによる異常な課金を防ぐことである。
前夜の推薦のために、ネットワークへ送ってよい。

順は、次のとおりである。

1. 雨の日は、雨天中止の予定、定期、TODO を、その日の候補から外す。定義とプールは残す。雨でない日は、雨天中止を問わず候補に残す。
2. 予定と、その日の曜日に合う定期を、それぞれの開始時刻どおりに置く。範囲の外でも、開始時刻から終了時刻まで置く。予定と定期の時刻が重なったときは、予定を置く。その回の定期は、その日の時間割に置かない。定義は残る。
3. 空きのうち、起床から終わりの時間までに入るところへ TODO を置く。どの TODO を置くかは Jev が決める。詰め方は、余裕のありなしに従う。
4. やりたいことも、同じプールの TODO として空きに入る。

例は、歯医者が 10:00 から 11:00、次の予定が 14:00、確定申告が 4 時間、洗濯が 1 時間のときである。
その 3 時間には洗濯を置く。
14:00 の予定を外して確定申告を置くのは、前夜のタスクごとの直しである。

材料が少なければ、予定と定期だけ、または短い時間割になる。

利用者は、出した時間割を見る。
提案を却下して、生成し直してよい。
生成し直すときも Jev を呼び、同じ 3 回に数える。
前夜の直しは、タスクごとである。

その日の時間割は、最新の一つを残す。
生成し直したら、前の案を上書きする。

---

## 記録

生成したカレンダーは、提案した内容のまま残す。
何をしようとしていたかである。
ブロックごとに、できた／できなかったを付ける。
一言日記は、計画の対象日の夜に書く。

その日にブロックがあるとき、終了が最も遅いブロックの終了時刻に、macOS の通知センターへ出す。
そのブロックは、予定でも、定期でも、TODO でもよい。
ローカルホストを起動しているあいだに、その時刻を迎えたとき出す。
ブラウザを閉じても、ローカルホストを起動しているあいだは出す。

時間割に載らなかった TODO は、プールに残る。
その日の予定は、その日の回で終わる。
新しい「やらなきゃ」や「やりたい」が浮かんだら、また TODO として預ける。

---

## 保存

データは SQLite ファイル一つである。
そのファイルを、その Mac のローカルに置いて動いてよい。
同じファイルを iCloud 上に置き、複数の Mac で共有できる。
共有の単位は、そのファイル一つである。
同じファイルは、二台の Mac から同時に開ける。
各 Mac は、その Mac 上の Golang でページを出す。
ページを出す Golang は、Mac ごとに別である。
保存先のパスは、差し替えられる。

生成した一日のカレンダー、ブロックごとのできた／できなかった、一言日記は、同じファイルに持つ。
